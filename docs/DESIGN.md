# Design and interaction notes

## Direction

Root Access treats the portfolio as a world with consistent rules. Signals travel, identities carry permissions, and healthy roots reflect explicit configuration checks. The visual system stays botanical and editorial: midnight blue, muted greens, dusty rose, cream, serif display text and restrained monospace annotations.

One primary motion system operates in the hero: depth and environmental response under the pointer. The investigation and greenhouse provide the meaningful secondary interactions; the terminal, cipher, hashes and discoveries reward curiosity. Navigation and project content remain direct.

## Public references inspected

- [Bruno Simon, Folio 2025](https://github.com/brunosimon/folio-2025): read the public README’s ordering of inputs, world systems, wind, lighting, interactive points, water and audio; inspected the repository’s published social image for environmental composition. The useful principle is a coherent world with coordinated systems. This garden does not reuse its code, artwork, vehicle navigation or 3D assets.
- [Folio 2019](https://github.com/brunosimon/folio-2019): inspected public setup documentation as historical context. No implementation was copied.
- [MDN: requestAnimationFrame](https://developer.mozilla.org/en-US/docs/Web/API/Window/requestAnimationFrame): read official timing guidance. Garden motion uses elapsed time, a capped delta and exponential easing, and explicitly stops for offscreen/hidden/reduced-motion states.

This was focused source research, not a claim to have surveyed every current viral student portfolio. Original artwork and interactions were built around Laleen’s brief rather than reproducing another person’s identity.

## How the feature ideas connect

1. A synthetic incident becomes a three-slip evidence desk with context, pinning and a reasoned decision.
2. Permissions become greenhouse keys, lifecycle scenarios and independently reviewed exceptions.
3. The system lens reveals the same world’s trust boundaries and endpoints.
4. The investigation desk provides native dragging plus equivalent pin buttons and keyboard controls.
5. Sound is material-specific, synthesized, opt-in, adjustable and brief.
6. The evidence guide cites public source sections. Local and actual provider modes are clearly distinguished.
7. A deliberately flawed scripted assistant invites challenge and teaches uncertainty without pretending to be a live model.
8. Growth comes from an explicit milestone registry. Missing project evidence cannot automatically become an accomplishment.
9. Eleven optional discoveries include a packet journey, source clue, Caesar cipher, SHA-256 comparison, encoding explanation and honeytoken.
10. The build notebook makes the mechanics inspectable with code excerpts and plain-language explanations.

## Boundaries and next content work

No puzzle gates core content. No fabricated résumé, experience, email, project findings, posts or proficiency. The browser never runs shell commands. Fictional signals are explicitly labeled and isolated from real machines. No live AI call, deployment, paid integration or publication is performed during the build.

The next meaningful content update is actual evidence: reproducible lab instructions, reviewed screenshots, rationale and findings. Add those to the case files and public guide corpus together. Additional visual complexity should earn its place through a coherent interaction and a mobile/reduced-motion fallback.
